# Development Process

## Task tracking

- GitHub issues are the active source of work.
- Work on one issue at a time. Do not begin the next issue without approval.
- `_docs/tasks.md` is the original backlog and a reference only.
- PM - grooms a task before anyone implements it, follows _docs/team/pm.md.
- Engineer - implements one groomed task, follows _docs/team/software-engineer.md.

## Issue workflow

1. Read the issue's goal, description, and acceptance criteria before starting.
2. Implement only the approved issue scope.
3. Run the relevant checks and review the acceptance criteria again before
   closing the issue.
4. Commit completed work regularly with a focused commit message.
